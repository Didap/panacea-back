# CI workflow - 2026-06-05

GitHub Actions CI for panacea-back. Runs on push to `main` and on every pull request.

## Pipeline (.github/workflows/ci.yml)

ubuntu-latest, Node from `.nvmrc` (22), `npm ci`. Steps: lint, typecheck, build, unit tests
(`npm test`), migrations, e2e.

A `postgres:16-alpine` service container mirrors docker-compose (db `panacea`, role
`panacea_admin`/`panacea_admin`), mapped to `localhost:5432`. The job `env:` provides the vars the
zod schema requires (DATABASE_URL on 5432, the JWT secrets, etc.) because jest does not load
`.env`. Migrations create the `panacea_app` RLS role and policies before the e2e run; the
`panacea_admin` creation in `0002_rls.sql` is guarded by an `IF NOT EXISTS` DO block, so it does not
collide with the service superuser. `permissions: contents: read` and a `cancel-in-progress`
concurrency group are set.

## Also in this change

- Declared `dotenv` (`^17.4.1`) as a direct dependency: `src/database/migrate.ts` imports
  `dotenv/config` but it was only present transitively via `@nestjs/config`.
- `test` script is now `jest --passWithNoTests`, so the unit-test gate is green until the first
  `*.spec.ts` lands under `src/`.

## Known gap (tracked in ROADMAP Phase 5)

CI proves migrations apply, not that the RLS policies enforce: v0 services use the admin
(BYPASSRLS) pool and the e2e seeds via an admin connection, so `panacea_app` and its policies are
never exercised. A dedicated isolation test (connect as `panacea_app`, set `app.current_user_id`,
assert cross-patient denial) is the recommended next hardening step.

## Verification

Locally, against a CI-equivalent Postgres, every gate is green: lint, typecheck, build, `npm test`
(no specs, exit 0), migrations, e2e (4/4). Both workflow files parse as valid YAML.
